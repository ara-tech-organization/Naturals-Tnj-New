# Naturals Thanjavur — Website

Premium redesign of the Naturals Thanjavur unisex salon site. React + Vite, hand-written
CSS, no UI framework and no animation library.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # -> dist/
npm run preview
npm run lint
```

## Where the content comes from

| Source | Used for |
| --- | --- |
| Client content document | Sitemap, page structure, all headings and body copy, SEO titles, meta descriptions, keywords, FAQs, service categories, CTA wording |
| naturalsthanjavur.com | Logo, brand colours, Poppins typeface, phone, email, address, hours, socials, published statistics, testimonials, salon photography, GTM container |

Nothing outside these two sources is invented. Anything the sources did not supply is
marked `PLACEHOLDER` in `src/data/site.js` rather than filled in with made-up detail.

## Design system

- **Brand plum** `#7E4798` — extracted from the live site's `--primary: 281 34% 36%`.
  The scale in `src/styles/tokens.css` is built around it, over warm ivory neutrals with
  a muted gold accent for eyebrow rules.
- **Type** — Poppins only, matching the corporate site, which declares exactly one
  family (`font-family: Poppins, sans-serif`). Headings get their editorial voice from
  scale, weight and tight tracking rather than a second family. **Self-hosted** — see
  Assets below.
- **Scale** — every font size and section space is a `clamp()` locked between 320px and
  1440px, so type and rhythm move continuously instead of snapping at breakpoints.
- **Breakpoints** — xs `<576` · sm `576` · md `768` · lg `992` · xl `1200` · xxl `1400`,
  used for layout re-composition only.

### The editorial layer

`src/styles/editorial.css` is loaded last and scoped entirely to `.editorial`, the class
the home page wraps itself in. It is a *register*, not a second design system: longer
section rhythm, Cormorant at full display size, hairlines where the base sheet uses
boxes, and photography allowed to run larger. Every rule in it refines a component that
already exists elsewhere.

Two markup consequences, both in `Ui.jsx`:

- `Chapter` — the editorial eyebrow (numeral, gold rule, label), so home sections read
  as entries in a contents list.
- `SectionHeading` now takes either a string eyebrow (wrapped in the standard eyebrow)
  or an element (rendered as-is), which is how a `Chapter` gets in.

To bring another page into the same register, wrap its return value in
`<div className="editorial">` and swap its eyebrows for chapters. Nothing else moves.

### The image registry

Images are **bundled from `src/assets`**, not served as static files. Every one is
imported once in `src/assets/index.js` and exposed as a single `IMG` object:

```js
import { IMG } from "../assets";

<img src={IMG.hairstyle} alt="…" />
image: IMG.makeup,
```

Two things this buys over string paths:

- Vite content-hashes each file (`hairstyle-CbgyKPPC.jpg`), so they can be served
  with immutable, long-lived cache headers and a replaced image busts its own cache.
- A wrong name is a **build error**, not a 404 discovered in production.

Adding an image: drop the file into `src/assets`, import it in `index.js`, add it to
the exported object. Nothing else needs to know the filename.

Two references can't use an import, and both are handled:

- **`src/styles/layout.css`** uses the logo as a CSS `mask`. It points at
  `url("../assets/logo.png")` — a path relative to the stylesheet, which Vite
  resolves and hashes like any other import.
- **`index.html`** preloads the LCP image, using `/src/assets/…` paths that Vite
  rewrites to the hashed URLs at build time.

Fonts stay in `public/fonts` because `src/styles/fonts.css` is generated by a script
and references them by stable absolute URL, and because `index.html` preloads them by
name — neither survives content hashing.

## Assets

The site makes **no third-party asset requests**. Images are bundled from `src/assets`
and fonts served from `public/fonts`, so nothing renders through fonts.googleapis.com,
fonts.gstatic.com or any image CDN. The only remaining external host is the Google Tag
Manager container carried over from the live site.

### Fonts

The live site's stylesheet declares exactly one real family — `font-family: Poppins,
sans-serif` — requesting weights 300-700 from Google's CDN with no `@font-face` of its
own. The redesign uses the same single family, self-hosted:

- **14 files, 128 KB.** Weights 300/400/500/600/700 plus italic 400/500 for `<em>` and
  inline notes.
- Only the **latin** and **latin-ext** subsets ship; Poppins' devanagari subset is never
  rendered by this site's copy.
- Identical faces are de-duplicated by content hash and collapsed into a single
  `@font-face` weight range, so a variable font never ships the same bytes twice.
- Two faces are preloaded in `index.html`: 400 for body, 500 for headings/nav/buttons.

To change weights, refetch `scripts/gf-poppins.css` from Google with the axes you want
and run:

```bash
python scripts/selfhost-fonts.py    # rewrites public/fonts + src/styles/fonts.css
```

`src/styles/fonts.css` is generated — don't hand-edit it.

`--font-display` and `--font-sans` in `tokens.css` are both Poppins, but kept as two
tokens on purpose: headings carry their own tracking, and a display face can be
introduced later by editing one line instead of 35 rules.

### Images

All 10 images published on naturalsthanjavur.com are bundled from `src/assets`
(`hairstyle.jpg`, `makeup.jpeg`, `skincare.jpeg`, `spa.jpeg`, `wellness.jpeg`,
`mens_grooming.jpeg`, `saloon.jpeg`, `Story.jpg`, `hero_bgimage.jpg`, `logo.png`),
alongside the five stock photographs the live site already used. Note that probing that
server for other filenames returns `200 text/html` for *anything* — it is a SPA
catch-all, not a real file — so ten is the complete set. The live bundle itself
references only five of them plus the logo.

**Stock, added for the service families the salon had no photograph of** — 17 files
(`bridal-portrait`, `bridal-jewellery`, `mehandi`, `salon-interior`, `hair-colour`,
`hair-texture`, `hair-spa`, `scalp-ritual`, `facial`, `facial-mask`, `body-polish`,
`reflexology`, `manicure`, `pedicure`, `mens-cut`, `beard-trim`, `executive-shave`).
`src/assets/CREDITS.json` records photographer, source URL and licence for each.

All 17 are **Unsplash License** — free for commercial use, no permission or attribution
required. Unsplash also serves *Unsplash+* results (Getty), which are indistinguishable
in search results but need a paid subscription; anything sourced later must be checked
against the `plus` flag on the photo's API record and rejected if set. A first pass here
picked 15 premium images before that check was added, so this is a real trap, not a
theoretical one.

These are stand-ins, not this salon. Swapping in the salon's own photograph is a file
overwrite in `src/assets` — no code change, because everything references the registry
key rather than a path.

Two legacy filenames do not describe their contents, so they are placed by what they
show, not what they are called: `beauty-services.jpg` is a black-and-white shot of empty
styling stations, and `saloon.jpeg` is a men's facial.

`logo.png` is pure white on transparency, so it is painted as a CSS mask
(`src/styles/layout.css`) to take brand plum on light surfaces and white on dark.

The favicon can't use the logo as-is for the same reason. `scripts/make-favicon.ps1`
crops the **naturals** wordmark out of `logo.png` by alpha bounds — dropping the tagline,
which is hopeless at icon sizes — and sets it white on a plum rounded square, writing
`public/favicon-32.png`, `favicon-64.png` (the 2x tab slot) and `apple-touch-icon.png`.
Re-run it if the logo ever changes.

The wordmark is ~4.7:1, so in a square tile it is always a thin band: it reads at 180px
and is a white smudge at the 16px a browser tab actually renders. Setting `$USE_GLYPH`
at the top of that script to `$true` swaps in the wordmark's own leading **n** instead,
which stays legible at tab size.

Packages & Combos is a section of `/offers` rather than a page: a combo is a bundle of
services already in the catalogue, governed by the membership terms printed alongside it.
`COMBO_PACKAGES` in `src/data/services.js` drives it — give an entry an `items` array and
the card lists its inclusions.

Locations and Testimonials are full pages with their own SEO and schema; they sit
outside the top bar so it stays legible at laptop widths (`SECONDARY_NAV` in
`src/data/site.js` — move an entry into `NAV` to promote it).

## Notes for deployment

- The site is a client-side SPA. `public/_redirects` covers Netlify; on other hosts add
  the equivalent rewrite of all paths to `/index.html`, or deep links will 404.
- `useSeo` writes per-route title/meta/canonical/OG/JSON-LD at runtime, which is correct
  for social crawlers and Google but not for crawlers that don't execute JS. If that
  matters, pre-render with `vite-plugin-ssg` or similar — every page component already
  renders cleanly under `renderToString`.
- The booking form has no backend. It validates, then hands the enquiry to WhatsApp on
  the salon's own number. Swap the `handoff` function in `src/components/BookingForm.jsx`
  for a POST once an endpoint exists; the validation stays as-is.

   flips `HAS_PRICES`, which removes the "rates confirmed in salon" panel automatically.

   `TEAM` in `src/data/site.js` marks them as placeholders.

   Real client and before/after sets drop straight into `GALLERY_GROUPS`.

8. **Combo inclusions.** The rate card names "Glow Up" but doesn't print what's in it, so
   the card on `/offers#packages` describes the shape of the bundle and routes inclusions
   to the salon. Fill the `items` array on that entry in `COMBO_PACKAGES` and it lists

   and De-tan as "if offered for men" — all four are kept, since they were already on the
   site. Men's World of Colors, Hair Ritual, Facial Add-ons and Mani-Pedi are likewise
   retained though the structure doesn't list them. Delete any the salon doesn't actually
